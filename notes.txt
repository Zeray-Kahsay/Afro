- Do not send images through your API to Azure Blob Storage
- Instead use: Frontend -> Request Upload URL -> Azure Blob Storage
- OR: Frontend -> Cloudinary
- Your API only stores metadata. 
React -> Upload Image -> Cloudinary -> Receive URL -> POST URL to API

Endpoint: POST /api/properties/{propertyId}/images

Request
{
  "images": [
    {
      "url": "https://res.cloudinary.com/...1.jpg",
      "isCover": true
    },
    {
      "url": "https://res.cloudinary.com/...2.jpg",
      "isCover": false
    },
    {
      "url": "https://res.cloudinary.com/...3.jpg",
      "isCover": false
    }
  ]
}

- This is React friendly and uploads images in parallel-- submits one Request
WHY URLs Instead of IFormFile ?? 
-- Because IFormFile couples your API to storage. URLs don't
-- Easy to switch from Cloudinary -> Azure Blob Storage

### Important security considerations 
| Concern              | Current implementation          | Required consideration                                                                   |
| -------------------- | ------------------------------- | ---------------------------------------------------------------------------------------- |
| Upload ownership     | Intent belongs to property      | Verify the authenticated user is authorized to manage that property                      |
| Image verification   | Cloudinary metadata             | Verify the resource type is actually `image`, not merely an asset with an allowed format |
| Database consistency | Transaction + concurrency token | Test simultaneous finalization requests                                                  |
Also, the Cloudinary verification operation should distinguish between:

Asset not found: return null.
Cloudinary unavailable or authentication failure: throw an exception.
Invalid asset metadata: reject finalization.

Never interpret a Cloudinary API outage as a missing image.

One more consideration: your current handler verifies 
assets before starting the database transaction.
 That is deliberate: external network calls should not hold SQL Server transactions open. The concurrency token protects finalization when two requests race.
